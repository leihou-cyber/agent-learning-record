# AI 学习笔记书写规范

用于在本项目中新增或修订学习笔记。默认用中文，先判断章节，再写内容；不要把未经验证的推测写成事实。

## 1. 章节归类

五个固定章节只能使用 `chapters.py` 中已有的 id：

- `application` 应用层：Agent、Agent Skill、工作流编排、产品化应用实践
- `connection` 连接层：MCP、Tool、Function Calling、外部系统接入
- `interaction` 交互层：System Prompt、User Prompt、上下文指令、输出协议
- `memory` 记忆层：Token、Context、Context Window、持久记忆、检索记忆
- `foundation` 基础层：LLM、Transformer、训练/推理基础和模型原理

归类依据是这条经验的主要问题，而不是内容中顺带提到的技术名词。Agent/Skill 配置默认归入应用层；只有当笔记重点是 MCP 或工具通信时才归入连接层。

## 2. 事实与证据边界

每条笔记都要区分：

- 已验证：有命令输出、测试结果、页面行为或文件路径支撑
- 已决定：用户或项目规则明确要求的方案
- 待验证：尚未运行、尚未观察或依赖外部环境的内容

禁止编造命令输出、截图、远端状态、测试结果和工具能力。失败也要记录失败原因、影响范围和下一步，不要把“理论上应该”写成“已经成功”。敏感信息只描述认证方式，不记录 Token、密码、Cookie、密钥或完整私密 URL。

## 3. 推荐结构

标题应描述一个可复用的结论，正文按需要采用以下顺序：

1. 所属章节与记录日期
2. 背景/要解决的问题
3. 核心概念或配置
4. 实际步骤与关键路径
5. 验证证据
6. 失败、边界和风险
7. 可复用结论/检查清单

配置类经验必须写清“文件在哪里、谁加载它、如何验证、何时不会生效”。不要只写操作命令而不解释其适用范围。

## 4. 双写边界

- 网页即时展示：写入 SQLite 的 `data/notes.db`
- Git 长期追踪：同步写入 `notes/<chapter>/YYYY-MM-DD-<slug>.md`
- `data/*.db` 是本地运行数据，禁止提交
- Markdown 与 SQLite 使用同一个标题和主体内容，避免网页内容与仓库记录脱节
- 写入前先按章节和标题查重；已有同名笔记应更新，不要重复创建

## 5. 完成检查

- [ ] 章节 id 是五个固定章节之一
- [ ] 标题具体、可检索、没有把多个主题混成一句空泛结论
- [ ] 已验证事实与待验证事项有明确区分
- [ ] 没有写入凭据、个人敏感信息或虚构证据
- [ ] SQLite 中可展示，Markdown 中可追踪
- [ ] 用 `db.list_notes(chapter)` 或等价查询确认保存结果
